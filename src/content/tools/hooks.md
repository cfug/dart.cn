with a package.

本指南说明钩子是什么，以及如何在 package 中使用它们。

## Introduction

## 简介

You can currently use hooks to do things
such as compile or download native assets (code written in
other languages that are compiled into machine code), and
then call these assets from the Dart code of a package.

目前可以用钩子做这些事：
编译或下载原生资源（用其他语言编写、
并编译成机器码的代码），
再从 package 的 Dart 代码调用这些资源。

Hooks are Dart scripts placed in the `hook/` directory of
your Dart package. They have a predefined format for their
input and output, which allows the Dart SDK to:

钩子是放在 Dart package 的 `hook/` 目录中的 Dart 脚本。
它们的输入和输出有预定义格式，这样 Dart SDK 就可以：

1. Discover the hooks.

   发现这些钩子。

1. Execute the hooks with the necessary input.

   用必要的输入执行这些钩子。

1. Consume the output produced by the hooks.

   使用这些钩子产生的输出。

Example project with a build hook:

带构建钩子的示例项目：

<FileTree>

- example_project/ // Project with hooks.
  - hook/ // Add hook scripts here.
    - build.dart 
  - lib/  // Use your assets here.
    - example.dart
  - src/  // Add native sources here.
    - example_native_library.c
    - example_native_library.h
  - test/ // Test your assets here.
    - example_test.dart

</FileTree>

## Hooks

## 钩子种类

Currently, build hooks and link hooks are available. To learn more, see the following.

目前可用的有构建钩子和链接钩子。更多内容见下文。

### Build hooks {:.no_toc}

### 构建钩子 {:.no_toc}

With build hooks, a package can do things such as
compile or download native assets such as C or Rust libraries.
Afterwards, these assets can be called from the Dart code of a package.

借助构建钩子，package 可以编译或下载 C 或 Rust 库等原生资源。
之后，可以从 package 的 Dart 代码调用这些资源。

A package's build hook is automatically invoked by the
Dart SDK at an appropriate time during the build process.
Build hooks are run in parallel with Dart compilation and
might do longer running operations such as downloading or
calling a native compiler.

package 的构建钩子会由 Dart SDK
在构建过程中的适当时机自动调用。
构建钩子与 Dart 编译并行运行，
可能会执行耗时较长的操作，例如下载或调用原生编译器。

Use the [`build`][] function to parse the hook
input with [`BuildInput`] and then write the hook output
with [`BuildOutputBuilder`]. The hook should place
downloaded and generated assets in
[`BuildInput.sharedOutputDirectory`][].

使用 [`build`][] 函数，用 [`BuildInput`] 解析钩子输入，
再用 [`BuildOutputBuilder`] 写出钩子输出。
钩子应把下载和生成的资源放到
[`BuildInput.sharedOutputDirectory`][]。

The assets produced for your package might depend on
[`assets`][] or [`metadata`][] produced by the build hooks
from the packages in the direct dependencies in the pubspec. Therefore,
build hooks are run in the order of dependencies in the pubspec, and cyclic
dependencies between packages are not supported when using hooks.

为你的 package 生成的资源，可能依赖 pubspec 直接依赖里
那些 package 的构建钩子所产生的 [`assets`][] 或 [`metadata`][]。
因此，构建钩子按 pubspec 中的依赖顺序运行。
使用钩子时，不支持 package 之间的循环依赖。

### Link hooks {:.no_toc}

### 链接钩子 {:.no_toc}

With link hooks, a package can filter, optimize, or tree-shake code assets
generated by build hooks before bundling them into an application.

借助链接钩子，package 可以在把代码资源打包进应用之前，
对构建钩子生成的代码资源进行过滤、优化或摇树优化。

The Dart SDK automatically invokes a package's link hook (`hook/link.dart`)
during the application bundling phase. Unlike build hooks, which run
for each package, link hooks run with application-level context so they
can inspect which symbols the application actually uses.

Dart SDK 会在应用打包阶段自动调用 package 的链接钩子（`hook/link.dart`）。
构建钩子按每个 package 运行，链接钩子则带有应用级上下文，
因此可以检查应用实际使用了哪些符号。

Use the [`link`][] function to parse the hook input with [`LinkInput`][] and
write the hook output with [`LinkOutputBuilder`][].
If tree-shaking removes all symbols for an asset, the link hook can omit
the asset entirely to avoid bundling it with the application.

使用 [`link`][] 函数，用 [`LinkInput`][] 解析钩子输入，
并用 [`LinkOutputBuilder`][] 写出钩子输出。
如果摇树优化移除了某个资源的全部符号，链接钩子可以完全省略该资源，
避免把它打包进应用。

### Environment variables {:.no_toc}

### 环境变量 {:.no_toc}

Hooks are executed in a semi-hermetic environment.
This means that `Platform.environment` doesn't
expose all environment variables from the parent process.
This ensures that hook invocations are reproducible and cacheable, and
don't depend on accidental environment variables.

钩子在半封闭的环境中执行。
这意味着 `Platform.environment` 不会暴露父进程的全部环境变量。
这样钩子的调用就可以复现、可以缓存，
并且不会依赖偶然存在的环境变量。

However, some environment variables are necessary for
locating tools (like compilers) or configuring network access.
The following environment variables are
passed through to the hook process:

不过，有些环境变量是定位工具（例如编译器）
或配置网络访问所必需的。
下列环境变量会传递给钩子进程：

*   **Path and system roots:**

    **路径和系统根目录：**

    *   `PATH`: Invoke native tools.

        `PATH`：调用原生工具。

    *   `HOME`, `USERPROFILE`: Find tools in default install locations.

        `HOME`、`USERPROFILE`：在默认安装位置查找工具。

    *   `SYSTEMDRIVE`, `SYSTEMROOT`, `WINDIR`: Process invocations and
        CMake on Windows.

        `SYSTEMDRIVE`、`SYSTEMROOT`、`WINDIR`：处理进程调用，
        以及 Windows 上的 CMake。

    *   `PROGRAMDATA`: For `vswhere.exe` on Windows.

        `PROGRAMDATA`：供 Windows 上的 `vswhere.exe` 使用。

*   **Temporary directories:**

    **临时目录：**

    *   `TEMP`, `TMP`, `TMPDIR`: Temporary directories.

        `TEMP`、`TMP`、`TMPDIR`：临时目录。

*   **HTTP proxies:**

    **HTTP 代理：**

    *   `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`: Network access behind proxies.

        `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`：经代理的网络访问。

*   **Clang/LLVM:**

    **Clang/LLVM：**

    *   `LIBCLANG_PATH`: Rust's `bindgen` + `clang-sys`.

        `LIBCLANG_PATH`：Rust 的 `bindgen` + `clang-sys`。

*   **Android NDK:**

    **Android NDK：**

    *   `ANDROID_HOME`: Standard location for the Android SDK/NDK.

        `ANDROID_HOME`：Android SDK/NDK 的标准位置。

    *   `ANDROID_NDK`, `ANDROID_NDK_HOME`, `ANDROID_NDK_LATEST_HOME`,
        `ANDROID_NDK_ROOT`: Alternative locations for the NDK.

        `ANDROID_NDK`、`ANDROID_NDK_HOME`、`ANDROID_NDK_LATEST_HOME`、
        `ANDROID_NDK_ROOT`：NDK 的其他位置。

*   **Nix:**

    **Nix：**

    *   Any variable starting with `NIX_`.

        任何以 `NIX_` 开头的变量。

Any changes to these environment variables
cause cache invalidation for hooks.

这些环境变量一旦变化，钩子的缓存就会失效。

All other environment variables are stripped.

其余环境变量都会被去掉。

## Assets

## 资源

Assets are the files that are produced by a hook and then
bundled in a Dart application. Assets can be accessed
at run time from the Dart code. Currently, the Dart SDK can
use the `CodeAsset` type, but more asset types are planned.
To learn more, see the following.

资源是钩子生成、然后打包进 Dart 应用的文件。
运行时可以从 Dart 代码访问这些资源。目前 Dart SDK
可以使用 `CodeAsset` 类型，以后还会增加更多资源类型。
更多内容见下文。

### CodeAsset type {:.no_toc}

### CodeAsset 类型 {:.no_toc}

A [`CodeAsset`][] represents a code asset. A code asset is a dynamic library
compiled from a language other than Dart, such as C, C++, Rust, or Go.
`CodeAsset` is part of the `code_asset` package. APIs provided by code assets
are accessed at run time through corresponding external Dart members annotated
with the [`@Native`][] annotation from `dart:ffi`.

[`CodeAsset`][] 表示一项代码资源。代码资源是用 Dart 以外的语言
（例如 C、C++、Rust 或 Go）编译而成的动态库。
`CodeAsset` 属于 `code_asset` package。代码资源提供的 API
在运行时通过对应的外部 Dart 成员访问，
这些成员带有来自 `dart:ffi` 的 [`@Native`][] 注解。

[`@Native`]: {{site.dart-api}}/dart-ffi/Native-class.html

### 添加依赖

To use a hook, you must first add the helper packages

要使用钩子，必须先把辅助 package
`hooks` 和 `code_assets` 加到 `pubspec.yaml`

1. `dart pub add hooks code_assets`.

   `dart pub add hooks code_assets`。

如果需要编译 C 源文件，还需要 package `native_toolchain_c`：

2. `dart pub add native_toolchain_c`.

### Create a build hook to generate native assets {: #create-hook }

### 创建构建钩子以生成原生资源

If you want to use a build hook to transparently compile
native assets (such as C or Rust libraries), which are then
made available to be called from the Dart code of a package,
create a `build.dart` script similar to the following:

如果想用构建钩子透明地编译原生资源（例如 C 或 Rust 库），
并让 package 的 Dart 代码能够调用它们，
请创建类似下面的 `build.dart` 脚本：

1.  In your Dart project, create or open `hook/build.dart`. 

    在 Dart 项目中创建或打开 `hook/build.dart`。

1.  In the `main` method, call the `build` function from
    `package:hooks/hooks.dart` and use the appropriate
    toolchain to compile the native library. For example:

    在 `main` 方法中，调用 `package:hooks/hooks.dart` 里的
    `build` 函数，并用合适的工具链编译原生库。例如：

    ```dart title="hook/build.dart" highlightLines=6
    import 'package:hooks/hooks.dart';
    import 'package:native_toolchain_c/native_toolchain_c.dart';

    void main(List<String> args) async {
      await build(args, (input, output) async {
        final packageName = input.packageName;
        final cLibrary = CLibrary(
          name: packageName,
          assetName: '$packageName.dart',
          sources: ['src/$packageName.c'],
        );
        await cLibrary.build(
          input: input,
          output: output,
        );
      });
    }
    ```

    The second parameter of `build` expects a function that it will pass two
    arguments to:

    `build` 的第二个参数需要一个函数，它会向该函数传入两个参数：

    * `input`: The read-only input for the hook.
      Includes information for the hook
      to produce the right asset type (for example,
      target OS, target architecture, output directory, and
      more). For details, see the [`BuildInput`][] class.

      `input`：钩子的只读输入。
      其中包含钩子生成正确资源类型所需的信息
      （例如目标操作系统、目标架构、输出目录等）。
      详情见 [`BuildInput`][] 类。

    * `output`: The write-only builder for the hook output. After the
      build hook reads the input, it produces an asset and
      then provides what it produced as the output.
      For details, see the [`BuildOutputBuilder`][] class.

      `output`：钩子输出的只写构建器。构建钩子读入输入后，
      会生成一项资源，再把生成的内容作为输出提供出来。
      详情见 [`BuildOutputBuilder`][] 类。

[`BuildInput`]: {{site.pub-api}}/hooks/latest/hooks/BuildInput-class.html
[`BuildOutputBuilder`]: {{site.pub-api}}/hooks/latest/hooks/BuildOutputBuilder-class.html

:::note
When naming your dynamic libraries, ensure the name is
consistent across all target architectures and SDKs.
On Apple platforms, Flutter's build system relies on
consistent filenames to correctly generate frameworks and XCFrameworks.
For more details, check out [Binding to native code][flutter-native]
on the Flutter documentation site.

为动态库命名时，请确保名称在所有目标架构和 SDK 上保持一致。
在 Apple 平台上，Flutter 的构建系统依赖一致的文件名，
才能正确生成 framework 和 XCFramework。
更多细节请查阅 Flutter 文档站上的
[绑定原生代码][flutter-native]。

:::

### Create a link hook to tree-shake native assets {: #create-link-hook }

### 创建链接钩子以对原生资源做摇树优化

:::version-note
Support for link hooks and recorded usage tree-shaking was introduced in
Dart 3.13.

链接钩子以及基于已记录用法的摇树优化从
Dart 3.13 开始引入。
:::

If your package generates native assets with a build hook (`hook/build.dart`),
you can add a link hook (`hook/link.dart`) to tree-shake unused code assets
before bundling.

如果 package 用构建钩子（`hook/build.dart`）生成原生资源，
可以再加一个链接钩子（`hook/link.dart`），
在打包前对未使用的代码资源做摇树优化。

During compilation, the Dart compiler records which `@Native` symbols are
actually referenced by the application and provides them to link hooks through
[`LinkInput.recordedUses`][].
If `input.recordedUses` is `null`, the link hook disables tree-shaking and
keeps all symbols.

编译期间，Dart 编译器会记录应用实际引用了哪些 `@Native` 符号，
并通过 [`LinkInput.recordedUses`][] 提供给链接钩子。
如果 `input.recordedUses` 为 `null`，链接钩子会停用摇树优化，
并保留全部符号。

1.  In your Dart project, create or open `hook/link.dart`.

    在 Dart 项目中创建或打开 `hook/link.dart`。

1.  In the `main` method, call the `link` function from
    `package:hooks/hooks.dart` and pass tree-shaking options to [`CLibrary.link`][].
    For example:

    在 `main` 方法中，调用 `package:hooks/hooks.dart` 里的
    `link` 函数，并把摇树选项传给 [`CLibrary.link`][]。
    例如：

    ```dart title="hook/link.dart"
    import 'package:hooks/hooks.dart';
    import 'package:native_toolchain_c/native_toolchain_c.dart';
    import 'package:record_use/record_use.dart';

    import 'record_use_mapping.dart';

    void main(List<String> args) async {
      await link(args, (input, output) async {
        final packageName = input.packageName;
        final cLibrary = CLibrary(
          name: packageName,
          assetName: '$packageName.dart',
          sources: ['src/$packageName.c'],
        );

        final linkerOptions = LinkerOptions.treeshake(
          symbolsToKeep: input.recordedUses?.calls.keys
              .cast<Method>()
              .map((e) => recordUseMapping[e.name]!),
        );

        await cLibrary.link(
          input: input,
          output: output,
          linkerOptions: linkerOptions,
        );
      });
    }
    ```

Dart symbols in bindings generated by tools such as `ffigen` don't always map
one-to-one to native C symbol names.
When generating FFI bindings, `ffigen` can automatically generate a mapping
(`recordUseMapping`) from Dart method identifiers to native symbols.
Map each recorded Dart method call (`input.recordedUses?.calls.keys`)
using `recordUseMapping` to pass the corresponding native symbols to
`LinkerOptions.treeshake`.

`ffigen` 等工具生成的绑定里，Dart 符号并不总是
与原生 C 符号名一一对应。
生成 FFI 绑定时，`ffigen` 可以自动生成从 Dart 方法标识符
到原生符号的映射（`recordUseMapping`）。
用 `recordUseMapping` 映射每一条已记录的 Dart 方法调用
（`input.recordedUses?.calls.keys`），
把对应的原生符号传给 `LinkerOptions.treeshake`。

When `symbolsToKeep` is `null` (for example, when `input.recordedUses` is
`null`), `LinkerOptions.treeshake` preserves all symbols in the native library.
When `symbolsToKeep` is an empty list (`[]`), meaning the application doesn't
reference any symbols from the library, `CLibrary.link` automatically skips
compiling and bundling the dynamic library entirely.

当 `symbolsToKeep` 为 `null` 时（例如 `input.recordedUses` 为
`null`），`LinkerOptions.treeshake` 会保留原生库中的全部符号。
当 `symbolsToKeep` 是空列表（`[]`），也就是应用没有引用该库的任何符号时，
`CLibrary.link` 会自动跳过动态库的编译和打包。

### Automatically bundled assets {: #generate-assets }

### 自动打包的资源

The hooks are run automatically when invoking the `run`, `build`, or `test`
commands. The resulting assets are stored in the output directory specified in
the hook input. The Dart SDK then automatically bundles those assets with
your Dart app so that they can be accessed at run time.

调用 `run`、`build` 或 `test` 命令时，钩子会自动运行。
生成的资源存放在钩子输入所指定的输出目录中。
随后 Dart SDK 会自动把这些资源与 Dart 应用打包在一起，
以便在运行时访问。

### Use assets {: #reference-assets }

### 使用资源

Assets are the files that hooks create. Once an asset is
created, you can reference it in your code and at run time
with its asset ID ([`assetId`][]). Asset IDs are structured
as `package:<package-name>/<asset-name>`. Build hooks can
only output assets in their own package. `CLibrary` in
the build hook in the previous example outputs the asset ID
`package:native_add_library/native_add_library.dart`, and is
based on the `packageName` and `assetName`.

资源是钩子创建的文件。资源创建之后，
可以在代码中和运行时用它的资源 ID（[`assetId`][]）来引用。
资源 ID 的形式是 `package:<package-name>/<asset-name>`。
构建钩子只能输出自己 package 中的资源。上例构建钩子里的
`CLibrary` 会输出资源 ID
`package:native_add_library/native_add_library.dart`，
它由 `packageName` 和 `assetName` 组成。

:::tip
As a best practice, use the Dart library URI where you
intend to use the code asset as the asset ID.
While you can use any asset ID that starts with your package name,
using the library URI enables Dart to
automatically connect the asset at run time without
needing to specify an `assetId` in the `@Native` annotation.

最好把你打算使用该代码资源的 Dart 库 URI 用作资源 ID。
虽然任何以 package 名开头的资源 ID 都可以用，
但使用库 URI 可以让 Dart 在运行时自动关联资源，
不必在 `@Native` 注解里指定 `assetId`。

:::

The following example illustrates how to bind to the native
C function `add` from `native_add_library.c` and call it:

下面的例子说明如何绑定 `native_add_library.c` 中的原生
C 函数 `add` 并调用它：

```dart title="my_package/lib/my_package.dart"
import 'dart:ffi';

@Native<Int32 Function(Int32, Int32)>()
external int add(int a, int b);
```

```dart title="my_package/bin/my_package.dart"
import 'package:my_package/my_package.dart';

void main() {
  print(add(24, 18));
}
```

The asset ID in `@Native` is optional and defaults to the
library URI. In the previous example, this is
`package:native_add_library/native_add_library.dart`, which
is the same asset ID as output from the build hook. This
enables Dart to connect an asset referenced at run time to
the one provided by the hook during the build process.

`@Native` 中的资源 ID 是可选的，默认是库 URI。
在上例中，它是 `package:native_add_library/native_add_library.dart`，
与构建钩子输出的资源 ID 相同。
这样 Dart 就能把运行时引用的资源，
连接到构建过程中钩子提供的那一项。

[`assetId`]: {{site.dart-api}}/dart-ffi/Native/assetId.html

### Test assets {: #test-assets }

### 测试资源

After you've written a hook that generates an asset and
you've used that asset in your Dart code, consider writing
a test to verify that the hook and the generated asset works
as expected.

写好生成资源的钩子，并在 Dart 代码中使用该资源之后，
可以考虑写一个测试，验证钩子和生成的资源是否按预期工作。

In the following example, a test is created for
`native_add_library.dart`, a script that references a
native C function called `add`: 

下面的例子为 `native_add_library.dart` 创建测试。
该脚本引用了名为 `add` 的原生 C 函数：

import 'package:native_add_library/native_add_library.dart';
import 'package:test/test.dart';

## Hook configuration {: #hook-configuration }

## 钩子配置

Pass custom parameters or local file paths to build and link hooks
from your project's build environment.
Configure these parameters under the `hooks` key in your `pubspec.yaml` file.
Currently, this block supports only the `user_defines` option.

可以从项目的构建环境向构建钩子和链接钩子
传递自定义参数或本地文件路径。
在 `pubspec.yaml` 的 `hooks` 键下配置这些参数。
目前这一块只支持 `user_defines` 选项。

### Configure user-defines {: #configure-user-defines }

### 配置 user-defines

Configure custom parameters inside the root package `pubspec.yaml` file,
or in the workspace `pubspec.yaml` file if you use a workspace.
Only end-users—the authors of the root app or package consuming
the dependencies—can configure user-defines.
Dependencies can't supply their own default user-defines.

在根 package 的 `pubspec.yaml` 中配置自定义参数；
如果使用工作区，则写在工作区的 `pubspec.yaml` 中。
只有最终用户（消费这些依赖的根应用或根 package 的作者）
才能配置 user-defines。
依赖本身不能提供自己的默认 user-defines。

The configured values under `user_defines` can be any JSON-compatible type,
such as booleans, strings, numbers, nested maps, or lists.
User-defines are filtered per package.
A hook inside `my_package` can only access keys configured under
`hooks.user_defines.my_package`.
It can't access the user-defines of other packages.

`user_defines` 下配置的值可以是任何与 JSON 兼容的类型，
例如布尔值、字符串、数字、嵌套映射或列表。
user-defines 按 package 过滤。
`my_package` 里的钩子只能访问
`hooks.user_defines.my_package` 下配置的键。
它不能访问其他 package 的 user-defines。

The following is an example of passing two user-defines
to the hooks of the `my_package` package:

下面的例子向 `my_package` 的钩子传递两个 user-defines：

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    my_package:
      enable_experimental: true
      custom_lib: assets/libnative.so
```

### Access user-defines in a hook {: #access-user-defines }

### 在钩子中访问 user-defines

To access configured user-defines in your
`build.dart` or `link.dart` hook script,
use the `input.userDefines` object:

要在 `build.dart` 或 `link.dart` 钩子脚本中
访问已配置的 user-defines，
请使用 `input.userDefines` 对象：

1. Read raw values using the bracket operator, such as `input.userDefines['key']`.

   用方括号运算符读取原始值，例如 `input.userDefines['key']`。

1. Resolve relative paths to a `Uri`
   using the `path()` method,
   such as `input.userDefines.path('key')`.
   This resolves the relative path against the directory of the `pubspec.yaml`
   where the user-defines are declared.

   用 `path()` 方法把相对路径解析为 `Uri`，
   例如 `input.userDefines.path('key')`。
   它会相对于声明这些 user-defines 的 `pubspec.yaml`
   所在目录来解析相对路径。

If the hook reads a resolved file or directory,
register it as a dependency using
`output.dependencies.add()`.
This ensures that the build system invalidates the cache and
re-runs the hook when the file changes.

如果钩子读取了解析后的文件或目录，
请用 `output.dependencies.add()` 把它登记为依赖。
这样文件变化时，构建系统会使缓存失效并重新运行钩子。

The following is an example hook script that accesses the
`enable_experimental` and `custom_lib` user-defines:

下面的钩子脚本示例会访问
`enable_experimental` 和 `custom_lib` 这两个 user-defines：

```dart title="hook/build.dart"
import 'dart:io';
import 'package:hooks/hooks.dart';

void main(List<String> args) async {
  await build(args, (input, output) async {
    final experimental = input.userDefines['enable_experimental'];
    if (experimental is! bool?) {
      throw const FormatException(
        'hooks.user_defines.my_package.enable_experimental must be a '
        'boolean (or omitted)',
      );
    }

    if (experimental ?? false) {
      print('Experimental features enabled.');
    }

    final customLibUri = input.userDefines.path('custom_lib');
    if (customLibUri != null) {
      final file = File.fromUri(customLibUri);
      output.dependencies.add(file.uri);
      // Use the file...
    }
  });
}
```
